Automatic language selection — 23 October 2026
The same language-config.js resolver is used on the landing page, project
pages, cookies and legal documents. Priority: a supported ?lang parameter,
a language-specific filename, a saved manual preference, then the first
supported entry in navigator.languages (navigator.language as fallback).
Unsupported lists fall back to Polish. Generic Polish HTML is a static
no-JS/SEO fallback, not an automatic language preference.

Only a manual selection in the picker or visible language links writes the
existing kova_site_language preference. Both localStorage and an essential
one-year cookie are used; blocked storage falls back to the cookie. If both
are blocked, language selection still works for the current page and URL.
Automatic detection and merely visiting a shared localized URL do not replace
a previous manual preference. Existing saved choices remain compatible.

Browser aliases cover regional tags, cmn for Mandarin, zh-Hant-HK/zh-MO for
Cantonese, pa-Arab-PK for Western Punjabi and legacy jw for Javanese.
The selector does not use IP geolocation or any external translation service.

Shared navigation — 24 October 2026
All public pages use the same sticky header, six primary links and language
control. Project pages share a secondary navigation and a breadcrumb trail;
information pages have their own contextual links. Active states distinguish
the current main section, subpage and selected landing-page anchor.
The static build uses the same header/context renderers as the browser.
Generic Polish navigation carries ?lang=pl so direct Polish links retain
their language when browser preferences or saved choices differ. Canonical
metadata remains free of language query aliases. Workspace remains separate.
Run npm run test:navigation with the local preview to verify real transitions.
